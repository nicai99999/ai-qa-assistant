# 工具调用（Tool Calling）

## 三个工具
| 工具 | 用途 | 何时不调用 |
|---|---|---|
| get_current_time | 当前时间 | 问历史事件时间 |
| list_documents | 列出知识库文档 | 问文档内容 |
| search_knowledge_base | 检索知识库 | 闲聊、问时间/文档列表 |

## 测试结果：6/6 全对
| 问 | 期望 | 实际 |
|---|---|---|
| 现在几点了？ | get_current_time | ✅ |
| 知识库有哪些文档？ | list_documents | ✅ |
| RAG 的完整链路是什么？ | search_knowledge_base | ✅ |
| 帮我查 SSE 和 WebSocket 的区别 | search_knowledge_base | ✅ |
| 你好 | 不调用 | ✅ |
| 现在几点 + 几份文档 | 两个都调 | ✅ |

## 发现
1. 模型会自己压缩 query（"RAG 的完整链路是什么？" → "RAG 完整链路"），
   这是隐式优化，不可控
2. 工具内 k=3 比主链路 k=5 小，导致 SSE 那题相似度从 0.834 掉到 0.704
   → 已在 tools.py 改为 k=5
3. 日志链完整：一次工具调用两行日志（retriever + tools）可完整追踪

## 一个隐蔽 bug：工具返回时的逐块截断

**现象**：问"SSE 和 WebSocket 的区别"，模型回答"没有找到直接对比"。
**排查**：
1. 先怀疑 k 太小 → 改成 k=5，相似度和答案都没变 → 排除
2. 再怀疑模型简化了 query → 三种措辞都测，都是 0.70 → 排除
3. 查 top-1 块内容 → 块长 356 字，含「双向」→ 答案在库里
4. 定位到工具代码 `text[:200]` → 「WebSocket 是双向的」在 200 字之后被截断

**根因**：检索正确，但工具交付给模型时逐块截断，砍掉了答案。

**修法**：去掉 `[:200]`。若需控长度，改为按总量预算截断，
而非逐块截断（宁可少给一块，不要砍一半）。

**代价**：工具返回 token 增加约 50%（1000 字 → 1900 字）。

**教训**：RAG 的每一段管道都可能存在隐式截断 ——
分块、上下文拼接、工具返回、Prompt 组装。
任何一处截断都可能静默吃掉答案，而监控指标完全看不出来。
