## 2. 两轮修复记录

### 修复 1：`retrieve()` 默认 collection 是 `rag_notes`（v1 旧索引）

**现象**：第 2 轮"RAG 的完整链路是什么？"答"资料中未提及"。
**证据**：召回的块编号是 `::0 ::53 ::57 ::58`，属于 v1 的 61 块体系。
**修法**：`retrieve()` 默认参数改为 `collection="rag_notes_v2"`。

### 修复 2：Prompt 把历史降级为"只能消歧，不能作答案来源"

**现象**：问"我叫什么名字"答"资料中未提及"。
**原因**：Prompt 第 4 条写"答案必须来自资料"，模型严格遵守，拒绝使用历史里的信息。
**修法**：加第 5 条——

> 如果问题是在询问对话中**用户自己说过的信息**（姓名、偏好、之前提过的事），
> 直接根据对话历史回答，并在末尾标注（来自对话历史）。

**结论：这不是"记忆没生效"，是"指令禁止使用记忆"。**

## 4. 两个重要发现

### 发现 1：代词问题（第 3 轮）是侥幸成功

```
第 3 轮 "它有哪些步骤？"
[5] 06_面试纲要汇总.txt::76  相似度 0.431   ← 正确答案在这，排第 5
```

- 同一个问题不带代词时，相似度是 **0.772**；带代词时掉到 **0.431**
- 能答对，只因为答案块刚好挤进 Top-5 最后一名
- **若 k=3，必然失败**

**结论**：对话历史只能帮模型"推断用户指的是什么"，**不改善检索本身**。
真正的解法是**查询改写**（Day 26）：

```
原问题："它有哪些步骤？"
→ 用历史改写："RAG 的完整链路有哪些步骤？"
→ 再检索
```

### 发现 2：第 1 轮"我叫小明，请记住"不该走检索

召回了 5 块不相关内容（最高 0.347），纯浪费 token，还让模型倾向于说"未提及"。

**企业做法是意图分流**：

```
用户输入 → 判断意图
              ├─ 闲聊 / 个人信息 → 直接走模型，不检索
              └─ 知识查询       → 走 RAG
```

## 6. 已知问题（不阻塞）

`src/reindex.py` 第 125 行的 id 生成：

```
python
ids = [f"{name}::{i}" for i, (name, _) in enumerate(chunks)]
```

`i` 是**全体块的全局序号**，不是"该文件内的第几块"。

后果：
- 同一文件的块 id 不连续（`06_xxx::76` 的下一个不一定是 `::77`）
- `retrieve_with_neighbors` 按 `::n±1` 找邻居会**取错块或取不到**
- **Day 23 中"相邻块扩展失效"的结论因此不可靠**，需修正 id 后重测

**不影响"重分块提升 Top-1（54.5%→72.7%）"的主结论。**
