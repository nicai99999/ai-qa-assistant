# 健壮性与日志

| 场景 | 触发方式 | 返回 | 类型 |
|---|---|---|---|
| 空问题 | 真实调用 | 问题不能为空。 | 真实链路 ✅ |

**8/8 通过，无一崩溃，无一暴露堆栈。**

## 设计要点
1. 异常收口在一层（`safe_qa`），业务层不写 try
2. 不按异常类名 except，改按"类名 + 文本特征"判断，跨 SDK 版本更稳
3. 输入错误用 warning，系统错误用 error + exc_info=True（带堆栈）

## 日志清单
每次调用必须能回答三项：耗时 / token / 成功失败。

## 真实 SDK 异常验证
- 真实类名：AuthenticationError
- 真实文本：Error code: 401 - {'error': {'message': 'Authentication Fails, Your api key: ****test is invalid...
- 翻译结果：API Key 无效或已过期，请检查 .env 配置。 ✅
- 结论：「类名 + 文本特征」判断法对真实 SDK 异常有效，跨版本更稳

## 日志踩坑
- 现象：一次检索打了 5 条日志，只有"召回数"在变
- 原因：logger.info 写在了遍历结果的 for 循环里
- 修正：挪到循环外，只在 return 前打一条
- 代价量化：5 轮对话 25 行噪音（应为 5 行）
- 教训：日志放错位置比没有日志更糟，会淹掉真正信号

## 隐私处理
- 日志不再记录用户输入原文，只记长度
