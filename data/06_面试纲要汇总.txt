1.2 RAG 核心（★ 最高频）
Q4：RAG 的完整链路？ ★★★
•骨架：文档解析 → 分块 → Embedding 向量化 → 存入向量库 → 用户问题向量化 → 相似度检索 Top-K → 拼进 Prompt → 模型生成 → 返回答案+来源
Q5：为什么要分块？
•骨架：① 模型上下文有上限 ② 整篇塞进去噪音太多、检索粒度太粗 ③ 分块后能精确定位到相关段落
Q6：分块大小怎么定？重叠多少？ ★★
•骨架：说你实际试过的参数 + 观察到的差异
•关键："我试了 200 和 500 两档，200 时召回更精确但上下文容易断裂，500 时上下文完整但容易混入无关内容。最后选了 ___，因为 ___。"
•重叠作用：防止一句话被从中间切断，导致语义丢失
Q7：为什么要向量检索？和关键词检索（BM25）区别？ ★★
•向量：比"语义相似"，能处理同义词/换述
•关键词：比"字面匹配"，精确但不懂同义
•加分："两者可以混合，关键词补精确性，向量补语义。"
Q8：Top-K 取多少？召回不准怎么办？ ★★
•骨架：K 太小漏信息，太大引入噪音且费 token
•优化手段：调 K、加相似度阈值过滤、改分块、加 Rerank 重排、混合检索
Q9：为什么选这个向量库？
•骨架：Chroma 本地跑、零部署、适合学习和单机；Milvus 适合大规模；pgvector 适合已有 PG
•❌ 别说"因为教程用的这个"
Q10：怎么评估 RAG 效果好不好？ ★★★（能答=加分）
•骨架：建评测集（N 个问题 + 标准答案）→ 跑 → 算命中率/正确率 → 改一个参数再跑 → 对比
•关键："我把命中率从 __% 提到 __%"，这个数字必须是你自己测的。
Q11：模型胡编（幻觉）怎么办？ ★★
•骨架：① Prompt 里明确"资料中没有就说不知道" ② 让答案带引用来源，可核对 ③ 提高检索质量（召回准了幻觉就少）
Q12：Embedding 是什么？
•骨架：把文本映射成高维向量，语义相近的文本向量距离近；维度由模型决定

批次 2｜Day 22–28 之后（流式 + 记忆）
2.1 流式
Q13：流式输出怎么实现的？ ★★★
•骨架：调模型时开 stream=True → 服务端按 SSE 增量返回（每个 chunk 是 delta）→ 逐段推给前端 → 前端边收边渲染
•加分："非流式和流式首字延迟差别很大，我实测 ___ 秒 vs ___ 秒。"
Q14：为什么流式体验更好？
•骨架：首字延迟低（用户立刻看到反馈），总耗时其实差不多
Q15：SSE 和 WebSocket 的区别？ ★★
•SSE：单向（服务端→客户端）、基于 HTTP、自动重连、轻量
•WebSocket：双向、独立协议、更重
•结论：大模型输出是单向推送，SSE 更合适
2.2 记忆（★ 能引出开源框架话题）
Q16：多轮对话怎么实现的？ ★★★
•骨架：会话 ID 标识用户 → 把历史消息（role + content）存起来 → 每次请求把历史一起发给模型
Q17：历史太长怎么办？ ★★★（这题答好能拉开差距）
•五种方案（按成本从低到高）：
a.滑动窗口：只留最近 N 条，简单便宜，适合短会话
b.摘要压缩：早期对话总结成摘要，再拼最近几轮
c.优先级截断：给消息打重要性标签，满了先淘汰低分的
d.向量记忆：历史事实入向量库，按需检索注入
e.工具结果裁剪：只留模型实际用到的部分
•加分："我的项目用了 ___，因为 ___。我了解到 Claude Code 这类工具走的是 ___ 思路，区别在于 ___。"
Q18：你项目里具体用了哪种？为什么？
•必须答你自己实现的那种，并说清代价（比如滑动窗口会丢早期信息）

批次 3｜Day 29–35 之后（工具 + 界面）
3.1 工具调用
Q19：工具调用（Function Calling）的完整流程？ ★★★
•骨架：① 把工具的描述（名字、参数 schema）给模型 ② 模型判断需要调用，返回工具名 + 参数 ③ 你的代码执行 ④ 结果回传给模型 ⑤ 模型给最终答案
Q20：有多个工具时，模型怎么决定用哪个？
•骨架：靠工具的名称和描述（description 写得好，模型才选得准）+ 模型自己推理
Q21：工具调用失败了怎么办？ ★
•骨架：① 把错误信息明确回传给模型，让它自己决定重试还是换方案 ② 加超时 ③ 兜底话术，不能让 agent 崩
Q22：为什么要限制 Agent 能调用哪些工具？ ★★
•骨架：安全边界。比如不能让模型调用删除数据、转账的接口；Prompt 注入可能诱导它调危险工具
Q23：什么是 Prompt 注入？怎么防？
•骨架：攻击者在输入里藏指令，让模型绕过原设定；防法：输入过滤、权限隔离、危险工具需人工确认

批次 5｜12 月面试期（Agent 概念，你从面经整理的重点）
这批现在不背，12 月开始。但可以先混个眼熟。
Q30：ReAct 是什么？完整流程？ ★★★
•Thought（想）→ Action（调用工具）→ Observation（看结果）→ 循环，直到得出答案
Q31：CoT 和 ReAct 的区别？ ★★
•CoT：只在"想"的层面推理，不行动
•ReAct：推理 + 行动交替
•一句话：CoT 是"想清楚再说"，ReAct 是"边想边试"
Q32：Multi-Agent 有哪些架构？优缺点？ ★★（面试要逐个分析）
•常见形态：协作式（多个 agent 分工，如规划者+执行者）、监督式（supervisor 派活给 worker）、层级式（多层管理）
•优点：职责拆分、可并行、单项更专精
•缺点：通信开销大、状态一致性难、调试困难、成本高（调多次模型）
•关键是能说出"什么时候不该用多 agent"（简单任务单 agent 就够）
Q33：Agent 和 Chain 的区别？
•Chain：流程固定，按预设顺序执行
•Agent：模型自主决定下一步（用不用工具、用哪个）
Q34：LangChain 里常见组件的作用？ ★★
•ChatModel：调模型
•PromptTemplate：提示词模板化
•OutputParser：结构化输出
•Tool：给模型的工具
•Retriever：检索
•Memory / Checkpointer：会话历史
Q35：LangGraph 是什么？为什么用图不用链？ ★★
•图 = 节点（步骤）+ 边（流转）+ 状态（共享数据）
•为什么用图：Agent 需要循环和条件分支，链是直线做不到
Q36：RAG 在 Agent 体系里是什么位置？ ★（你的原洞察很准）
•RAG 是 Agent 的一种工具/一个检索步骤，本身不等于 Agent
•模型没有私域知识，所以 RAG 仍是主流解决方案
Q37：Skill 是什么？为什么企业爱用？
•骨架：把常见任务封装成可复用的技能模块；开发快、门槛低、复用性强
