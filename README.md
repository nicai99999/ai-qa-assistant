# AI 问答助手（RAG + 多轮对话）

一个基于 Python + LangChain 的本地文档问答系统。
上传文档 → 语义检索 → 带引用出处的回答，支持多轮对话与上下文管理。

> 这个项目不是"调通 API 的 demo"。每一处优化都有对照实验和数据支撑，
> 见下方「实验与结论」。

## 功能

- 📄 **文档入库**：PDF / Markdown / TXT → 分块 → 向量化 → 存入 Chroma
- 🔍 **语义检索**：Top-K 相似度召回，支持 metadata 过滤
- 💬 **带引用回答**：每个结论标注 `[1] [2]`，附来源文件与块号
- 🧠 **多轮对话**：会话隔离、历史管理、代词改写
- 🛡️ **健壮性**：5 类异常统一翻译成人话，不暴露堆栈
- 📊 **成本可观测**：每次调用记录耗时、token、成功/失败

## 已知局限

1. **语义相似 ≠ 可答性**：高相似度块可能不含答案，需 rerank 或混合检索
2. **改写不稳定**：同一问题两次改写结果不同（temperature=0 也不保证确定性）
3. **评测集规模小**：仅 11 题可答，结论代表性有限
4. **意图未分流**：闲聊类问题也会走检索，浪费 token
5. **CLI 入口**：目前用实验脚本启动，未封装为正式命令

## 实验与结论

### 1. 重分块：Top-1 从 54.5% 提升到 72.7%

| 方案 | Top-1 | Top-K |
|---|---|---|
| 原分块（块长中位 70 字） | 54.5% | 90.9% |
| 重分块（chunk_size=400, overlap=80） | **72.7%** | **100%** |

评测集 20 题（11 可答），关键词匹配打分。
**根因**：块过碎导致标题与正文分离，标题块与问题同义但无答案。

### 2. 上下文管理：三种策略对比

| 策略 | 能否记住第 1 轮的关键信息 | 末轮 Prompt 长度 |
|---|---|---|
| 滑动窗口 | ❌ | 2668 |
| 摘要压缩（初版 prompt） | ❌ | 2362 |
| 摘要压缩（改进 prompt） | ✅ | ~2600 |
| 优先级截断 | ✅ | 2677 |

**结论**：摘要策略的成败由一句 prompt 决定，属"调参依赖型"；
优先级截断是规则型，+9 字符换确定性，最终采用后者。

### 3. 查询改写：相似度提升 23 个百分点，但不解决可答性

| 问 | 改写后 | 改写前 | 改写后 | 端到端 |
|---|---|---|---|---|
| 它有哪些步骤？ | RAG 的完整链路有哪些步骤？ | 0.4768 | 0.7652 | ✅ |
| 它有什么优点？ | RAG 有什么优点？ | 0.4165 | 0.6647 | ❌ 未提及 |
| 这个方法有什么缺点？ | RAG 的完整链路有什么缺点？ | 0.5481 | 0.7144 | ❌ 未提及 |

**结论**：改写解决"代词无实词"，**不解决"文档里有没有答案"**。
三题全被导向同一块——语义相似度衡量的是主题相关，不是可答性。

### 4. 流式输出

首字延迟 197 ms，总耗时 932 ms（同一个问题）。

### 5. 健壮性


8 类异常场景全覆盖：空输入 / 超长输入 / 401 认证失败 / 额度不足 / 限流 / 超时 / 断网 / 未知异常。
全部返回中文提示，无一崩溃，无一暴露堆栈。

## 快速开始
> 仓库内的 PDF 未上传（体积原因），可自行把文档放进 `data/` 后执行上面的建索引命令。

```bash
git clone https://github.com/nicai99999/ai-qa-assistant.git
cd ai-qa-assistant
uv sync
cp .env.example .env    # 填入 DEEPSEEK_API_KEY 和 embedding 服务的 key
uv run python src/reindex.py              # 建索引（需先把 pdf/txt/md 放进 data/）
uv run python -m ai_qa_assistant          # 开始对话
